## 1. 研究动机与贡献定位

几乎所有混沌图像加密方案（CIES）都只在**算法层和软件层**做安全评估（统计/差分/暴力/抗噪裁剪），而其在**硬件域**——尤其是设计与测试阶段的潜在漏洞——几乎无人审查。作者的核心论断：即使一个 CIES 通过了全部软件层测试，攻击者仍可以从硬件实现侧"注入故障"轻易瓦解它。

**核心贡献**：
1. 提出三种面向硬件实现的故障注入攻击模型：**结构攻击**（structure）、**状态变量攻击**（state-variable）、**参数攻击**（parameter），分别对应"削减加密轮数 / 篡改状态变量寄存器 / 扰动混沌映射参数"三条路径；
2. 在 **Raspberry Pi 3B+** 上用**电压故障注入**（voltage fault injection, VFI）硬件实测三种攻击，百万次级触发实验统计故障率/重启率/崩溃率随 glitch 时长的变化规律；
3. 给出四类防御对策（冗余计算、运行时域校验、频数统计监控、不规则时钟）。

这是知识库 98 篇中**第一篇"攻击方"视角**的论文，此前 97 篇全部是"构造+指标"的防守方叙事，方法论上形成互补。

## 2. 被攻击目标 CIES 结构（Section II）

攻击对象是一个面向 IIoT 的 CIES（作者实现/改造的 DNA 编码类方案），核心组件：

### 2.1 密钥与混沌系统（TDLM）

- 10 个子密钥 $K_0,\dots,K_9$：$K_3\sim K_7$ 分别作 Tent 映射 $\eta(i+1)=\min\{\eta(i)/\theta,\ (1-\eta(i))/(1-\theta)\}$ 与 Circle 映射 $\theta(i+1)=\theta(i)+\Omega-(E/2\pi)\sin(2\pi\theta(i))\bmod 1$ 的初值与参数；$K_8,K_9$ 为 Chebyshev 映射 $\xi(i+1)=\cos(p\cdot\arccos\xi(i))$ 的初值与控制参数（$p\in[2,6]$）；
- 三个映射各迭代 $t$ 次，输出小数部分生成 **TDLM**（三维耦合 Logistic 型映射）的初值：
  $$x(i+1)=\alpha x(i)(1-x(i))+\beta y^2(i)x(i)+\gamma z^3(i)$$
  $$y(i+1)=\alpha y(i)(1-y(i))+\beta z^2(i)y(i)+\gamma x^3(i)$$
  $$z(i+1)=\alpha z(i)(1-z(i))+\beta x^2(i)z(i)+\gamma y^3(i)$$
  其中 $\alpha\gg\beta,\alpha\gg\gamma$（故整体保持 Logistic 抛物线特性，为 Property 1 埋下伏笔）；
- 迭代 $M\times N$ 次得三序列，量化出**控制序列**：
  $$U(i)=\lfloor x(i)\cdot T\rfloor\bmod 8,\quad V(i)=\lfloor y(i)\cdot T\rfloor\bmod 8,\quad W(i)=\lfloor z(i)\cdot T\rfloor\bmod 256,\quad T>10000$$

### 2.2 加密流程（五步）

① **子图像置乱**：$4\times4$ 子块内像素 shuffle（256² 图像 → 4096 子块）；② **行/列旋转**（基于 $U$ 的 3 比特控制比特循环移位，$h(U(i),j)=(j-2U_2-U_1-4U_0)\bmod 8$）；③ **DNA 编码**（基于 $V$ 在 8 条规则中选 1 条，Table I）；④ **DNA XOR**（基于 $W$，Table II）；⑤ DNA 解码还原像素。

## 3. 三类故障注入攻击模型（Section III）

### 3.1 结构攻击——打 loop 的比较器与半加器

初始化部分末尾是一个 for 循环（Algorithm 1：测试 $i^*<M\times N$ + 更新 $i^*$）。其硬件实现中：
- **测试**由数字比较器实现（三位输入：$A,B$ 与级联使能；三输出 $F_{A>B},F_{A=B},F_{A<B}$）。故障使比较器在 $A<B$ 时输出错误的 $\hat F_{A>B}$，循环提前退出，**加密轮数减少 $M\times N-i^*+2^j$**；
- **更新**由寄存器 + 行波半加器实现，第 $j$ 个半加器故障导致索引 $\hat i^*$ 算错，$U,V,W$ 序列错位。

**后果**：$U,V,W$ 变短，旋转/DNA 操作"缺随机数"，密文**前半正确、后半只剩 shuffle 结果**——而 shuffle 本身几乎不改变图像视觉内容，攻击者直接读出明文轮廓。

### 3.2 状态变量攻击——IEEE 754 单比特翻转 + 发散性证明

对存储状态变量的寄存器注入故障（float32 格式，最大正规数 3F7FFFFF），单比特翻转落在三个部位：
- **尾数部分**：误差 $(1/2^{23-i})e^{-127}$，幅度小，状态留在 $(0,1)$ 内；
- **指数部分**（$e_i:1\to0$）：同上小扰动；**（$e_i:0\to1$）与符号部分**：状态变量**离开定义域** $(0,1)$，引发连锁灾难——

**Property 1（关键定理）**：若故障状态变量 $\hat x(r)\in(-\infty,\epsilon_1)\cup(\epsilon_2,+\infty)$，则 $\hat x(r+1)\le-1$ 且 $\hat x(r+2)<\hat x(r+1)$（单调递减、不再回归定义域）。证明利用 $\alpha\gg\beta,\gamma$ 把耦合项压掉，单变量化为 Logistic 抛物线左侧的单调逃逸。几个迭代后**全部状态变量小于 $-2^{31}$**，转 int 后一律饱和为 $-2147483648$，PRNG 输出**均匀/全零**。

**后果链**（非常工程化的推演）：$U(j)=0\Rightarrow$ 旋转失效（$I^{**}(j)=I^{*}(j)$）；$V(j)=0\Rightarrow$ DNA 固定用规则 0；$W(j)=0\Rightarrow$ 全 A 序列 XOR 恒等于对方——**三层密码操作全部退化为恒等映射，密文≈shuffle 后图像**。

### 3.3 参数攻击——用 W 序列差分收缩密钥空间

翻转 Logistic 参数 $\alpha$ 尾数第 $i$ 位 $g$（$\alpha$ 以 3.xx 存储，故 $i\in\{0,\dots,20\}$）：
$$\Delta\hat z(n+1)=\hat f(z)-f(z)=(-1)^{g+1}\cdot\frac{1}{2^{22-i}}\cdot z(n)(1-z(n))\quad\text{(式 4)}$$
由 $T\cdot z(n)=W(n)+l\cdot256$（$l$ 有界整数，式 5）枚举 $z(n)$ 候选，再由 $\Delta\hat W(n+1)$ 反推故障位 $g$ 与位置 $i$；**注入第二次不同故障** $\hat\alpha_2$，利用 $\hat\alpha_1,\hat\alpha_2$ 的差异把 $\alpha$ 收缩至 $(3.53-\hat\alpha_1+\alpha,\ 3.81-\hat\alpha_2+\alpha)$ 量级窄区间——实验参数 3.7125 被成功锁定，**密钥空间塌缩**。

## 4. 电压故障注入实验（Section IV）

- **平台**：Raspberry Pi 3B+（SoC 电源轨 1.2 V，电源管理芯片 XR77004）+ VFIE（FPGA + 放大器 + 继电器组成触发与脉冲生成）+ N 沟道 MOSFET 把 SoC 电源轨瞬时短接到地；PC 端 Python/Jupyter 控制流程与分析密文；
- **标定**：C 语言 if-else 探针程序 + 100 万次以上触发统计——glitch 时长 200 ns 时故障/重启/崩溃率 = 0.22%/0.11%/0.07%；550 ns 升至 0.78%/0.82%/0.61%；**850 ns 故障率见顶**，之后重启/崩溃率飙升、故障率反降（电源管理芯片介入）；
- **攻击结果**（256×256 "Village" 灰度图）：
  - 结构攻击：在第 **11,929** 次循环迭代处成功触发，$U,V,W$ 序列截短，密文部分退化为 shuffle 图；
  - 状态变量攻击：在第 **4,971** 次 TDLM 迭代处成功，PRNG 输出全零，旋转/DNA/XOR 三层全失效；
- **量化指标（Table III）**：正常密文 MSE 10006.49 / PSNR 8.16 dB / **NPCR 99.5956%**；结构攻击后 1775.43 / 15.67 dB / **76.67%**；状态攻击后 1012.86 / 18.11 dB / **72.33%**——NPCR 从"安全指标"变成"攻击效果度量"，密文直方图由平坦变为集中，视觉泄露一目了然。

## 5. 防御对策（Section V-B）

1. **冗余计算**（redundancy computation）：关键运算双份执行比对（经典但作者未给 overhead 数字）；
2. **计算检查**：在随机位置校验 $x,y,z\in(0,1)$——抓住 Property 1 的"逃逸定义域"特征，**实现成本几乎为零**；
3. **统计测试**：维护长 256 的频数数组 $F$，实时检查 $F(i)\approx F(j)$——直接检测 PRNG 塌缩为均匀/全零；
4. **不规则时钟**：加密完成后闲置的 Tent/Circle/Chebyshev 映射继续作 PRNG 生成**不规则时钟**驱动 CIES，同时抗侧信道与参数攻击（引文献 [50]）。

## 6. 不足

1. **攻击目标代表性有限**：被攻击 CIES 是作者自己实现/改造的方案（DNA 编码 + 顺序执行假设），比较器/半加器故障模型绑定该实现的 loop 结构；对 FPGA 并行流水实现、对无 loop 计数结构（如查表式 PRNG）的攻击外推性未讨论；
2. **故障模型理想化**：攻击分析假设"精确单比特翻转"，而 VFI 实测产生的是粗粒度随机故障（百万次测试只给成功率统计曲线，未建立"故障物理特征→攻击成功"的定量因果链）；11,929/4,971 这类成功迭代点的"可重复命中"问题（需不需要碰运气、要试多少次）没有量化；
3. **参数攻击威胁模型偏强**：需要攻击者能获得 $W$ 序列相关信息/部分明密文对，在真实 IIoT 摄像头场景假设偏高；
4. **防御全是原则性建议**：无 overhead、无性能代价量化、无任何一条对策的实现验证——"怎么防"停留在 checklist 层面；
5. **平台与场景的差距**：RPI 3B+ 是通用 SoC Linux 平台，不是真实 IIoT 嵌入式环境；未做 STM32/FPGA 等 bare-metal 实现上的实测（时钟门控、双核锁步等 MCU 自带防护是否有效均未触及）；
6. "选择明文攻击在硬件上不可行（攻击者无法控制智能相机输入）"的论断过于绝对——边缘设备固件逆向、测试接口（JTAG/UART）残留都是现实入口。

## 7. 可借鉴之处

1. **硬件域威胁建模清单**：结构（loop 计数器/比较器）→ 状态（寄存器单比特翻转）→ 参数（密钥存储区）三类故障，恰好对应任何嵌入式加密实现的三个攻击面——自己做混沌加密硬件（如 cipherflow U 盘类产品）时可直接当 threat model 模板逐条自查；
2. **Property 1 式的发散性证明模板**："故障态逃逸定义域 → 单调发散 → PRNG 塌缩"三步推导，写法干净（单变量化 + 抛物线单调性），可用于自己方案的抗故障安全性分析，反过来也提示设计时**避免状态变量可逃逸 (0,1) 的单峰结构**；
3. **运行时域校验 + 频数监控**（对策 2、3）：几条指令即可实现的轻量完整性自检，可直接加入 STM32 图像加密工程的固件（结合 096 的 STM32 实现路线）；
4. **不规则时钟**（对策 4）：闲置映射二次利用 + 抗侧信道，思路新颖且与混沌系统"多出来的映射"天然契合；
5. **NPCR 反向用法**：把 NPCR/直方图从"方案宣传指标"翻转成"攻击效果度量"，写攻击类论文的呈现手法值得学；
6. **VFI 平台复现路线**：FPGA + MOSFET 短路电源轨 + if-else 探针标定，整套装置成本低廉，适合本科毕设/竞赛/实验课复现（比激光/电磁注入门槛低得多）。

## 8. 与知识库已有论文的关联

- **vs 096（Lv 2026, IEEE TII, 忆阻多环 Rulkov STM32 图像加密）**：096 做了完整 STM32 硬件实现与 DSP 验证，但**完全没有硬件安全/故障分析**——本文正好是 096 缺失的那一块；096 若要在"硬件实现"卖点上继续走，本文的三类攻击是必须回应的问题，096 笔记"不足"部分可直接对接；
- **vs 097（Liu 2026, CSF, 2D-CICFM）/ 095（Deng 2026, TCSVT, 复值 HNN）/ 082（DNA 编码正弦混沌）**：这三篇都是"构造+软件指标"的防守方叙事，本文攻击目标恰是 DNA 编码类 CIES——软件指标全过 ≠ 硬件安全，并置阅读正好构成"红蓝对抗"完整图景；

- **方法谱系**：Chengqing Li 团队长期做混沌密码**分析**（选择明文破解 DNA-IES 等），本文把分析战场从算法层推进到硬件层，延续了该团队"攻击驱动设计"的研究路线；
- **对个人课题的直接意义**：混沌加密产品化（cipherflow）若走向硬件形态，本文是**必读的安全基线**——尤其是"测试阶段即注入故障"的威胁（内部人/代工厂场景）在 U 盘类产品代工模式下完全成立。
